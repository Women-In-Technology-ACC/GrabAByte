## Understanding Collaboration
Github is not just about writing code or having a backup of your projects. It's about working together and collaboration. It helps team:
- Track problems
- Organize tasks
- Plan releases
- Document project details


Even if you don't write much code yet, you can contribute by opening issues, organizing tasks, writing documentation, etc.

👉 Think of GitHub like a group planner or shared notebook — everyone sees what’s going on, and no one has to wonder what the next step is.

## Issues
GitHub issues are a core feature within GitHub repositories and are used for tracking, planning, and discussing work related to the project. They serve as a centralized place to manage various aspects of a project's development.

Although you *can* interact and create issues from the command line, *most* people use the GitHub web interface when dealing with Issues, so we will too!

Key characteristics and uses for GitHub Issues include:
- Tracking work
- Collaboration and discussion
- Organization and planning
- Breaking down workload
- Integration with development workflow
- Customization


Lets walk through creating an issue:
1. Login to GitHub and go to your Grab a Byte Workbook Repo.
2. Go to the "Issues" tab (second from the left next to the "<> Code" tab)
3. Here is a list of issues, but you shouldn't have any yet. Create a new issue by pressing the "New issue" button on the right
4. Add the title "Complete Lesson 8" and add the description: "Finish the Collaboration Intermediate Grab a Byte Lesson"
5. In the right hand panel: assign yourself
6. Leave the rest alone for now.
7. Notice how you can add rich text as well as attachments to your description
8. Click the "Create" button in the bottom right

It looks a lot like a Pull Request, right? Right! We can add comments and emojis just like we can in a PR!

Notice also how you can make a sub issue! If you click the drop down you will notice you can also add an existing issue as a sub issue!

Keep this issue open for now.

## Labels & Milestones
Labels and Milestones are tools used to categorize, organize, and track issues and pull requests, facilitating project management and collaboration.

**LABELS**:
- Categorize and classify issues, pull requests, and discussions.
- Filter and Search for specific types of issues or pull requests.
- Customization to create, edit, and delete labels, defining custom categories that fit the specific needs of your project.
- Visual Cues because labels often have customizable colors, providing quick visual cues about the nature or status of an item.

Let's try it!
1. Back in your GitHub issue, click on the gear button next to "Labels" in the right hand menu
2. Scroll through the list and choose any label
3. Click outside of the labels box and see how the issue has changed. 
4. Go back into the Labels menu and click "Edit labels"
5. It will take you to a new page. Click on "New label"
6. A pop up will appear, lets give it the title "needs more fun"
7. For description lets give it "This need way more fun!"
8. For the color give it this fun pink color: "#ff57d1"
9. Click "create label"

Click on "Issues" to see the list of open issues (which should only be this one). Click on the issue we're working on and leave it open.


**MILESTONES**:
- Time-based Grouping to group issues and pull requests that are intended to be completed within a specific timeframe.
- Progress Tracking to provide a clear overview of the progress towards a specific goal.
- Release Planning to plan and track the features and bug fixes targeted for an upcoming release
- Prioritization to help teams focus on the most critical task for that specific period.
- Association with issues and pull requests to indicate their inclusion in that particular set of work

Lets try it together:
1. Back in your issue, click the gear next to milestone in the right hand menu
2. The list should be empty but if you start typing you'll notice how you can create a milestone
3. Type out "GAB: GitHub" and click ```Create a new milestone: "GAB: GitHub```
4. That creates the milestone and adds it to the list and the issue. Click out of the box and see how the issue changes. 
5. In the events list of the issue, you will see your milestone added. Click the milestone and see a list of all issues that are associated with that milestone
6. Notice how there is a progress tracker under a group of buttons click the "Edit" button
7. See how you can edit the title, add a description or add an end date. Lets add an end date of December 13th. 
8. Click save changes and it will take you back to the list of issues. 

Leave this open and we will return later.


***SO*** Labels are color-coded tags for organizing issues and Milestone are collections of issues tied to a goal/date

## Github Projects
GitHub Projects are a project management tool integrated within GitHub that allows users and teams to plan, track, and organize work. They are distinct from repositories, as a single project can encompass work from multiple repositories or even just ideas and tasks not yet associated with code.

Key features and functionalities of GitHub Projects include:
- Flexible views
- Integration with GitHub data
- Customizable fields
- Automation with Workflows
- Organization and collaboration
- Templates
- Insights

Let's work on it together!
1. Back in your GitHub repo, click on the "Projects" tab in the top menu.
2. Click on the "+ New project" button
3. See a list of templates. If you are familiar with Trello, Clickup, Microsoft Planner, Jira, etc. you will see, this is just like that. But this is not a project management lesson, this is a GitHub lesson so....
4. Click on "Team Planning" from the templates list
5. And call the project "Learning GitHub" and click "Create Project"
6. Notice the different views available at the top and the "buckets" in the current view. 
7. In the "Todo" Bucket at the bottom, click the "+ Add item"
8. You can create a new task but we want to press the "+" button
9. Click "Add item from repository"
10. From the dropdown menu, make sure that your Grab a Byte repo is chosen
11. Click the "Complete Lesson 8" Issue we made earlier (the icon should be a circle with a dot in the center)
12. Click "Add selected items" and click out the box and look at your board. 
13. Drag and drop the new task you added to the next bucket
14. Go back to your repo
15. Click on the Issues tab and the issue we've been working on. See how the issue has changed. Click the drop down on the "Learning GitHub" project in the right menu. 
16. See all the additional ways your can edit and customize the issue task
17. Click the drop down on the "Close issue" button at the bottom, notice the different ways you can close an issue. 
18. Lets just close the issue as completed.
19. Refresh the page and look at the task in the projects list on the right menu... notice how it switched to Done :)
